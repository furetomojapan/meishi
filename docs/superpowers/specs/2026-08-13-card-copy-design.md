# 名刺コピー機能（管理画面） — 設計

## 背景・目的

管理者が、既存ユーザーの名刺の内容・デザインをすべてコピーして、新しいIDのユーザーとして複製作成できるようにする。

主な用途：
- 仕様変更（例：自己登録IDのランダム化）が「今後の新規登録にしか反映されない」場合に、既存ユーザーをコピー経由で新しい方式のアカウントへ移行する手段として使う（コピー後、必要なら元アカウントを管理画面から削除する）
- 似た内容の名刺を複数作る際のひな形としても使える

対象：管理画面（`isAdminMode`）のみ。利用者本人向けの「自分の名刺を複製する」機能は対象外。

## UI

Library一覧の各ユーザー行に、既存の削除ボタンの隣へ「コピー」ボタン（アイコンボタン）を追加する。

クリックすると`appPrompt`で新しいIDの入力を求める：
- バリデーションは既存の「新規ユーザー追加」入力と同じ（半角英数字・アンダースコアのみ、`registeredNames`と重複不可、空不可）
- キャンセルすれば何もしない

## コピー対象／非対象

コピーする：
- `displayName`（表示名）
- `links`（リンク一覧）
- `profile`（会社名・肩書き・名前・連絡先・アピール文・フォント・サイズ・色・位置・背景・テーマカラー等の全デザイン設定）
- `profile.frontImageUrl` / `backImageUrl`（独自背景画像の実データ。＋G機能）
- `plan`（PRO/FREE）
- `plusG`（＋G権限）
- お試し期間（`trialEnd`）・有料PRO期限（`proEnd`）— **残り日数をそのまま引き継ぐ**（コピー元がすでに期限切れの場合は引き継がない＝コピー先は期限なしでスタート）
- タグ（`tags`）

コピーしない：
- PIN（新規は未設定。本人が初回アクセス時に6桁PINを設定する、通常の新規作成と同じ挙動）
- `publicId` / `tagPublicId`（新規に自動採番される。既存のものを流用しない）
- `licenseKey`

## 実装方式

バックエンド（`gas_backend.js`）の変更は不要。フロントエンドから既存の管理者向けルートを順番に呼び出すだけで実現する：

1. `admin_create_user`（新しいID）
2. `admin_save_user`（`displayName` / `links` / `plan` / `profile`〈画像URL込み〉 / `plusG`をコピー元の値で送信）
3. コピー元の`trialEnd`が現在時刻より先（未期限切れ）なら、残り日数を計算して`admin_set_trial`を呼ぶ
4. コピー元の`proEnd`が現在時刻より先なら、残り日数を計算して`admin_set_pro`を呼ぶ
5. コピー元にタグがあれば`admin_save_tags`で新しいIDにコピー

各ステップは既存の管理者アクションと同じ`gasPost`呼び出しパターンを踏襲し、成功/失敗をトースト通知で表示する。途中のステップが失敗しても、それまでの内容は反映済みのまま新規ユーザーとしてLibrary一覧に残る（通常のアカウント作成〜編集の流れと同じ扱いとし、失敗時は管理者が編集パネルから手動で直せる）。

## 影響範囲

- `src/App.jsx`：Library一覧のボタン追加、コピー実行関数の追加のみ
- `gas_backend.js`：変更なし
- `tests/gas_mock_test.cjs`：既存の`admin_save_user`/`admin_set_trial`/`admin_set_pro`/`admin_save_tags`ルート自体はテスト済みのため、新規のバックエンドテストは不要。フロントエンドのオーケストレーション自体はこのプロジェクトに自動テストの仕組みがない（手動確認）

## 非対象（YAGNI）

- 利用者本人による自己複製機能
- コピー元/コピー先の一括選択・複数同時コピー
- コピー履歴の記録
